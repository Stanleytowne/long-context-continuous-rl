#### 1. **`chunk_long_text()`** - Lines 505-580
Smart text chunking with overlapping windows.

**Features:**
- Supports both tokenizer-based and character-based chunking
- Configurable chunk size and overlap
- Returns structured chunk information (text, indices, token counts)
- Handles edge cases (empty text, single chunk)

**Parameters:**
- `text`: Source long text
- `chunk_size`: Maximum tokens per chunk (default: 2048)
- `overlap`: Overlapping tokens between chunks (default: 256)
- `tokenizer`: Optional tokenizer for accurate token counting

**Returns:**
- List of chunk dictionaries with metadata

---

#### 2. **`extract_qa_pair()`** - Lines 583-625
Extract question-answer pairs from model-generated text.

**Features:**
- Parses `<question>...</question>` and `<answer>...</answer>` tags
- Robust fallback when tags are not found
- Returns extraction success status

**Parameters:**
- `text`: Model-generated text containing QA pair

**Returns:**
- Dictionary with `question`, `answer`, and `extraction_success` keys

---

#### 3. **`get_gen_longtext_qa_data()`** - Lines 628-799
**Proposer Phase**: Generate QA pairs from long text.

**Purpose:**
- Model sees text segments and generates questions requiring text knowledge
- Creates training data for the proposer role

**Key Features:**
- Automatic text chunking for long documents
- Multiple chunk sampling strategies: random/sequential/weighted
- Optional reference QA pairs for curriculum learning
- Configurable reference inclusion probability
- Comprehensive logging and debugging output

**Parameters:**
- `long_text`: Source text to learn from
- `target_data_len`: Number of QA pairs to generate
- `content_max_length`: Max prompt tokens
- `output_path`: Parquet file output path
- `chunk_size`, `overlap`: Chunking parameters
- `use_chunking`: Enable/disable chunking
- `chunk_sampling_strategy`: How to sample chunks
- `reference_qa_pairs`: Optional existing QA for reference
- `include_references`: Probability of including references (0.0-1.0)
- `prompt_manager`: Optional dynamic prompt manager

**Output Format:**
```python
{
    "data_source": "gen_longtext_qa",
    "prompt": [{"role": "user", "content": "..."}],
    "text_segment": "...",
    "chunk_id": 0,
    "question": "",  # Filled by model
    "answer": "",    # Filled by model
    "ability": "longtext_qa",
    "extra_info": {
        "chunk_id": 0,
        "chunk_token_count": 2048,
        "has_references": True/False
    }
}
```

---

#### 4. **`get_pred_longtext_qa_data()`** - Lines 802-889
**Solver Phase**: Answer questions WITHOUT seeing the text.

**Purpose:**
- Model must answer based on learned knowledge from SFT warmup
- Tests knowledge retention and internalization

**Key Features:**
- Only provides questions (no text access)
- Ground truth stored for reward computation
- Supports dynamic prompts via prompt_manager
- Automatic upsampling if insufficient data

**Parameters:**
- `qa_pairs`: QA pairs generated by proposer
- `target_data_len`: Number of prediction tasks
- `content_max_length`: Max prompt tokens
- `output_path`: Parquet file output
- `prompt_manager`: Optional dynamic prompts

**Output Format:**
```python
{
    "data_source": "pred_longtext_qa",
    "prompt": [{"role": "user", "content": "Question: ..."}],
    "question": "...",
    "answer": "",  # To be filled by solver
    "reward_model": {
        "style": "llm_judge",
        "ground_truth": "..."  # Used for evaluation
    },
    "extra_info": {
        "metric": "pred_longtext_qa",
        "original_chunk_id": 0
    }
}
```

---

#### 5. **`get_judge_longtext_qa_data()`** - Lines 892-982
**Judge Phase**: Compare solver's answer with ground truth.

**Purpose:**
- Train judge to evaluate answer quality
- Optional component (can use external LLM judge instead)

**Key Features:**
- Compares generated answer with ground truth
- Provides question context for evaluation
- Format-based reward (judge produces valid score)

**Parameters:**
- `qa_pairs_with_answers`: QA pairs with both GT and generated answers
- `target_data_len`: Number of judge tasks
- `content_max_length`: Max prompt tokens
- `output_path`: Parquet file output
- `prompt_manager`: Optional dynamic prompts

**Output Format:**
```python
{
    "data_source": "judge_longtext_qa",
    "prompt": [{"role": "user", "content": "Judge: ..."}],
    "question": "...",
    "ground_truth_answer": "...",
    "generated_answer": "...",
    "reward_model": {
        "style": "format",
        "ground_truth": ""  # Judge just needs valid score format
    },
    "extra_info": {
        "metric": "judge_longtext_qa"
    }
}
```

## 🎯 Design Decisions

### 1. **Chunking Strategy**
- Supports both tokenizer-based (accurate) and character-based (fast) chunking
- Overlapping chunks prevent knowledge fragmentation at boundaries
- Configurable sampling strategies for curriculum learning

### 2. **Data Format**
- Parquet format for efficient storage and loading
- Consistent schema across all three phases (gen/pred/judge)
- Rich metadata in `extra_info` for analysis and debugging

### 3. **Prompt Management**
- Supports both static and dynamic (prompt_manager) prompts
- Easy transition from hardcoded to optimized prompts
- Backward compatible with existing codebase patterns

### 4. **Error Handling**
- Graceful degradation when extraction fails
- Upsampling when insufficient valid data
- Extensive logging for debugging

### 5. **Code Style**
- Follows existing codebase conventions
- English comments throughout
- Clear function signatures with type hints
- Comprehensive docstrings
